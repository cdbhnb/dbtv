# 影片评分（TMDB）

评分来自 TMDB 用户，10 分制，与豆瓣评分相互独立。自动显示在可见影片卡片、预览浮层和详情页。未配置、没有投票、没有可靠匹配及网络失败均不会伪造分数。

## TMDB 榜单与选集排序

- 电影／电视剧页右上角「排序」默认保留源内资源（按更新）。切换评分最高、热门、本年热门新作、本月热门新作、本周趋势、最新上映后，展示 TMDB 的全局分页榜单，而不是把当前资源站的一页资源重新排序。
- 热门榜 `/discover` 也改为 TMDB 电影／电视剧榜单。站内历史记录、收藏、管理员统计及旧统计接口保留，不再用于公开热门榜。
- 评分最高按 TMDB `vote_average.desc`，电影至少 300 人评分，电视剧至少 100 人；不代表豆瓣评分，也不冒充 TMDB 官方加权 Top Rated 排序。
- 热门采用 TMDB `popularity.desc`；本年／本月是本年／本月首次上映或开播作品，按当前热度排序。它们不是历史月榜或年度观看次数，TMDB 未公开真实播放次数。
- 本周趋势使用 `/trending/movie/week` 或 `/trending/tv/week`，代表最近 7 天趋势；此模式不叠加分类、地区、年份和语言筛选。
- 新片按首次上映／开播日期降序，默认近 90 天且至少 5 人评分；手选年份则查看该年新作，不显示未来上映日期。日期边界统一按 Asia/Tokyo；月榜、年榜会在自然月／年切换。
- 其余榜单的分类由 TMDB genre 接口提供，地区使用原产国家／地区，语言是原始语言，不是配音语言；与资源站的分类和地区体系分开显示。
- 点击 TMDB 卡片进入本站全站搜索，不直接把 TMDB ID 当资源站 ID；搜索沿用原有数据源开关与访问权限。结果保留目标年份提示，需核对同名版本，外部榜单不保证存在可播放资源。
- 榜单复用现有服务器令牌，最多 4 个请求并发，缓存 15 分钟，内存缓存最多 200 项，每用户每分钟最多 60 次。失败不会切回虚假的站内观看榜。
- 播放器和详情页均提供正序／倒序按钮，浏览器记住显示顺序；排序不改变正在播放的集数，上一集／下一集始终按剧情正序。

参考：https://developer.themoviedb.org/docs/popularity-and-trending 、https://developer.themoviedb.org/reference/discover-movie 、https://developer.themoviedb.org/reference/discover-tv 。

## 每页数量与大屏布局

评分榜、分类页、源片库统一提供「自动 / 24 / 48 / 96」。自动按浏览器可用宽度选择：小于768px为24部，768–1799px为48部，1800px起96部；不是按显示器物理分辨率判断。偏好只保存在当前浏览器 localStorage，不修改账号、源组或数据库。切换数量或自动模式跨越宽度档位时回到第一页，保留分类、排序和其他筛选。仍使用上一页／下一页，不改为滚动加载。

TMDB 每个上游分页20部，后台按本站页的全局偏移读取对应上游分页，再切片；例如48部的第二页是第49–96项，不会简单跳过或重用整个上游分页。页数按本站每页数量换算，最多访问上游500页。上游榜单本身随时间变化，跨缓存时段的排名仍可能变化。

源站即使忽略 pagesize，固定返回20条或7条，后台也会合并后再按本站数量分页。分类页的多个子分类使用稳定交错顺序，按影片ID去重后分页，地区、年份、语言在分页前核对。短时内存缓存只保存公共影片摘要，不缓存用户权限；输出仍执行已有源和分类权限检查。封面与缺失封面补查按可见区域加载，96部不代表同时下载96张图。

每次远程合并最多96个上游请求、并发最多4个，最多缓存8个筛选流、2分钟、单流最多20000条去重记录；深页或过宽筛选会明确提示缩小范围，不伪造完整结果。上游重复返回同一页会停止并提示；网络失败返回错误，可重试，不把失败当成无更多内容。源内本来不足、上游资料异常或权限过滤后，实际数量可能少于所选数量。

## 启用

1. 在 https://www.themoviedb.org/settings/api 申请自己的 API 使用权限，复制 **API Read Access Token**，不是短版 API Key。
2. 管理后台 → 网站设置 → 影片评分 · TMDB：粘贴令牌，勾选启用，点击单独的「保存评分设置」。留空保留旧令牌，页面永不回显令牌。
3. 或设置服务器环境变量 `TMDB_READ_ACCESS_TOKEN` 并重启。环境变量优先，此时后台不能覆盖它。Docker Compose 已通过 `env_file: .env` 传入；systemd/PM2/Termux 请确保启动进程能读取此变量。浏览器端绝对不要使用 `VITE_TMDB_*`。
4. 点击「测试已保存的连接」，确认服务器能连接 TMDB 且令牌有效；再打开一部片名及年份准确的影片详情。出现 TMDB 分数后可点击进入原平台条目，检查标题、年份和评分人数。

没有真实令牌时只能验证待配置、权限、故障降级和测试桩流程，不能声称真实评分已启用。非商业和商业使用条件、署名要求见 https://developer.themoviedb.org/docs/faq 。商业项目需自行向平台确认授权。

## 匹配、性能与隐私

- 服务器固定请求 `api.themoviedb.org`，仅发送片名；本地核对片名、年份及电影/剧集类型。重名有歧义不自动选择，不因分数高或结果靠前就认为是正确影片。
- 不发送登录账号、用户历史、播放 URL。明确标记为成人/福利/伦理等分类不请求 TMDB。请勿把 TMDB 数据用于其条款禁止的内容。
- 可见卡片才读取；浏览器批处理最多 20 部，服务端最多 4 个并发请求；同作品合并请求。每用户每分钟上限 120 部。
- 成功及无匹配结果缓存 24 小时，保存在现有 SQLite `Setting` 表中，以 `rating:cache:` 区分。每十分钟惰性清理过期数据并缩减至最多 1000 项；并非视频缓存，不下载影片。网络/鉴权错误退避一分钟且不写入持久评分。
- 更改配置会清空评分缓存，不删除影片、JSON 播放源或观看记录。无需修改数据库结构或运行额外迁移。
- `rating:` 命名空间（含缓存和令牌）不通过公共 `/api/settings` 返回；评分配置接口限管理员，令牌只写不读。SQLite 备份可能包含令牌，勿上传 GitHub；可优先用环境变量管理密钥。
- 外部评分错误不会阻断搜索、详情或播放。各源片名/年份不准确时宁缺毋滥，自动匹配不保证覆盖所有影片，后续可扩展管理员手动绑定。
