# 账号专属今日推荐

入口：导航「今日推荐」(`/recommendations`)，以及首页分类导航下的精选区域。依赖现有 TMDB 令牌，不需要额外 AI 付费密钥。

## 能做什么，以及不是什么

这是本地可解释的内容推荐引擎，不是外部大模型、聊天机器人或声称经过专门训练的 AI。它把本账号的有效播放进度、收藏和主动选择的题材组合成偏好，再参考 TMDB 关联推荐、类型、平均分和评分人数筛选候选。

同账号、同一天、相同有效信号采用稳定的今日片单；不同账号独立计算。相似兴趣的账号仍可能有部分重合，不能保证所有账号的每部影片都不同。新账号没有足够信号时，明确展示“正在认识你”，以评分筛选的探索片单作为起点，不伪造喜好分析。

## 信号与质量规则

- 读取当前账号最近120天内最多150条进度记录、最多60条收藏，只使用仍有权限且启用的数据源，忽略隐藏影片及明确成人类来源。
- 一般进度需达到180秒且至少10%；短片（不超过600秒）至少50%，或已有完成标记。现有字段是保存的播放进度，不是逐秒观看时长，拖动进度可能影响判断。用户可在页面中关闭使用历史。
- 同标题/已知年份的多集和跨源记录去重，重复集数不会无限叠加权重。收藏权重3.5，完成标记1.7，一般有效进度1，结合时间衰减；主动选题材权重4。
- 最多取4部高权重样本，按片名、已知年份及媒体类型保守匹配 TMDB。没有可靠匹配就不推断该条偏好，界面显示成功匹配数量与参考样本。
- 从电影、剧集的高分/热门池、偏好题材池、最多2部兴趣样本的 TMDB 关联推荐中获取候选。
- 题材中的“科幻／奇幻”对应电影科幻或奇幻，以及 TMDB 合并的电视科幻/奇幻分类；“剧集”包含电视剧、番剧等电视节目。
- 候选至少6.5分；电影至少100人评分、剧集至少50人。对低样本评分用 `(v × R + m × 6.5) / (v + m)` 降权，电影m=300、剧集m=100，展示的仍是原始 TMDB 分数和人数，而不是改写平台分数。
- 排序综合质量、题材匹配、TMDB关联、按账号与日期确定的探索扰动和多样性。候选充足时，约20%的槽位保留品质探索，电影/剧集混选时避免单类型占比超过约75%。如果没有足够候选，不填充低分或虚假影片。
- 排除有效播放过、已收藏和手动标为不感兴趣的作品；不感兴趣列表每账号最多300项。点击卡片全站找片，沿用现有源开关与权限，不保证外部条目一定有可播放资源。

## 隐私与存储

- 所有个性化 API 从登录会话确定账号，不接受通过 `userId` 参数读取他人画像。响应使用 `Cache-Control: private, no-store` 和 `Vary: Cookie`。
- 偏好、不感兴趣和当日片单保存在原 SQLite `Setting` 表的 `recommend:prefs:账号ID`、`recommend:daily:账号ID` 中；每账号只保留最新一份片单，不增加逐日文件或迁移数据库。
- 整个 `recommend:` 命名空间不通过公共 `/api/settings` 返回，备份仍可能包含私人喜好及样本，需妥善保管，不要上传 GitHub。
- TMDB 只接收匿名作品/题材查询，不接收账号标识、完整观看历史、收藏列表或播放地址。未接外部大模型。
- 用户可以关闭使用播放进度和收藏，不会删除原记录。保存新偏好或“不感兴趣”后，缓存指纹改变，后续分析重新生成。每日按 Asia/Tokyo 切换日期。
- 重复读取命中账号专属快照；公共 TMDB 元数据可在服务器缓存15分钟，缓存不包含个性化画像。推荐接口每账号每分钟最多20次，同时最多20份不同画像分析。
- 部分 TMDB 请求失败时明确标注“部分资料未响应”，不保存不完整日片单；全部失败时显示可重试错误，源内片库与播放不受阻断。

## 验证

自动测试覆盖短暂预览去噪、跨集去重、质量/人数门槛、未来影片排除、稳定的每日探索、不同账号的兴趣差异、源权限、隐藏影片、私人缓存隔离、禁用历史、冷启动说明、个性化请求鉴权与降级。测试数据只用内存适配器，不创建真实账号或伪造用户观看记录。

运行：`npm run lint`；`node --import tsx --test server/tests/*.test.ts`；`npm run build`。
